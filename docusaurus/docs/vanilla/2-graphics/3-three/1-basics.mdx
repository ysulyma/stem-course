### index.html

export const typeModule = $ultraBasic.line(`type="module"`);

<CodeBlock language="html" showLineNumbers={typeModule.index+1} title="index.html">
  {typeModule.toString()}
</CodeBlock>

This marks the file `scene.js` as an [<abbr title="ECMAScript">ES</abbr> module](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules). ES modules are the modern way to break JavaScript code into reusable chunks and share them. Specifically, this is what lets us use the [`import`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import) syntax in `bases.js`.

This is also what necessitates [running a local server](#running-a-local-server): for security reasons, ES modules can't be run in `file://` mode.

export const importMap = $ultraBasic.line(`type="importmap"`).to(`</script>`);

<CodeBlock language="html" showLineNumbers={importMap.startIndex+1} title="index.html">
  {importMap.toString()}
</CodeBlock>

This is an [import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script/type/importmap). This tells the browser how to resolve `"three"` to an actual JS file. Without import maps, we would have to write

<CodeBlock language="js" showLineNumbers={importThree.index+1} title="scene.js">
  {importThree.toString().replace("three", importMap.toString().match(/"three": "(.+)"/)[1])}
</CodeBlock>

which is harder to read and maintain.

### scene.js

Now let's take a look at the JavaScript.

#### import syntax

export const importThree = $minimalJs.line(`from "three"`);

<CodeBlock language="js" showLineNumbers={importThree.index+1} title="scene.js">
  {importThree.toString()}
</CodeBlock>

This is a modern [import](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import) statement. It loads all of THREE.js into a variable called `THREE`. Unlike older module-loading solutions, the variable `THREE` is not available outside of `scene.js`—this is one advantage of the new syntax.

Another advantage of the new import syntax is that it allows tooling to statically determine which imports you actually use. This enables **bundlers** (covered in the Framework part of the course) to perform [tree shaking](https://developer.mozilla.org/en-US/docs/Glossary/Tree_shaking), meaning they get rid of code that you don't actually use. **If you use a bundler**, then it is more efficient (in terms of file size) to only import what you need:

```js
import {
  BoxGeometry,
  Mesh,
  MeshBasicMaterial,
  PerspectiveCamera,
  Scene,
  WebGLRenderer
} from "three";
```

However, in plain JavaScript it doesn't make a difference. (Although browsers can do the equivalent of tree-shaking, most libraries are not structured in a way that would enable this, since downloading one big file is usually faster than making roundtrips for several small files.)

#### Adding objects
The most interesting part is:

export const createMesh = $minimalJs.range("const geometry", "scene.add");

<CodeBlock language="js" showLineNumbers={createMesh.startIndex+1} title="scene.js">
  {createMesh.toString()}
</CodeBlock>

This is the typical pattern for adding objects to a THREE.js scene. Most objects in THREE.js are <ThreeDocs item="Mesh" />es. Every Mesh has an associated <ThreeDocs item="BufferGeometry" /> defining its shape and a <ThreeDocs item="Material" /> defining its color/appearance. The specific ones we used here are:

- <ThreeDocs item="BoxGeometry" prefix />
- <ThreeDocs item="MeshBasicMaterial" prefix />

:::warning
If you change the `MeshBasicMaterial` to another material, such as a <ThreeDocs item="MeshPhongMaterial" prefix />, the cube will disappear! This is because we haven't yet added any [lights](https://threejs.org/manual/#en/lights) to our scene.
:::

## Refactored code

Here is a refactored scene with boilerplate extracted and various niceties added. We will use this setup as the base for everything going forward.

<LivePreview>

  ```js title="scene.js"
  import * as THREE from "three";
  import { OrbitControls } from "three/addons/controls/OrbitControls.js";

  import { makeScene } from "./three-utils.js";

  // create scene
  const { scene } = makeScene({
    animate: () => {
      cube.rotation.x += 0.01;
      cube.rotation.y += 0.01;
    },
    camera: {
      position: [6.12, 3.59, 5.43],
      up: [0, 0, 1], // math convention
    },
    container: document.getElementById("container"),
    controls: OrbitControls,
  });

  // add lights
  const ambientLight = new THREE.AmbientLight(undefined, 0.1);
  scene.add(ambientLight);

  const pointLights = [
    { position: [0, 5, 5], intensity: Math.PI, decay: 0 },
    { position: [0, 0, -2], intensity: Math.PI },
  ];

  for (const config of pointLights) {
    const pointLight = new THREE.PointLight(
      config.color,
      config.intensity,
      config.distance,
      config.decay,
    );
    pointLight.position.set(...config.position);
    scene.add(pointLight);
  }

  // axes helper
  scene.add(new THREE.AxesHelper(5));

  // cube
  const geometry = new THREE.BoxGeometry(1, 1, 1);
  const material = new THREE.MeshBasicMaterial({ color: 0x00ff00 });
  const cube = new THREE.Mesh(geometry, material);
  scene.add(cube);
  ```
